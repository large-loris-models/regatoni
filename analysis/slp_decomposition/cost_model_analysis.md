# Cost-Model Barrier Analysis — SLP Vectorizer

The synthesis pass (rounds 1+2, |N|=22, |T|=21) reaches **341 / 378
fuzzer-reached SLP fns (90.2 %)** but leaves **37 named cost-model
internals unreached**, plus a long tail of anonymous lambdas inside the
big cost-model functions. This document traces each of those unreached
cost-model functions back to a covered-frontier function, derives the
tree shape that would force the call chain to fire, groups the gaps,
then attempts directed synthesis.

## Methodology

1. Aggregate raw probe coverage across every minimal seed (N1..N22),
   every directed synthesis seed (S_*), and every composition seed
   (`composed/`). Collapse template arguments and parameter lists to
   per-fn entries; preserve namespaces (`(anonymous namespace)::`,
   `slpvectorizer::`, `BoUpSLP::`).
2. Overlay onto the static call graph
   (`docs/slp_decomposition/callgraph.json`, 940 nodes, generated by
   `scripts/analysis/extract_callgraph.py`). Match callgraph nodes to
   raw probe symbols via last-component + suffix-of-qualifier.
   Result: **158 / 940 callgraph nodes reached**, **782 unreached**;
   after dropping anonymous numbered lambdas (`lambda@NNNN`)
   **439 named fns unreached**.
3. Filter to cost-model semantics by class/keyword:
   `Cost`, `Reduction`, `Reorder`, `Schedule`, `BinOpSameOpcode`,
   `BaseShuffle`, `getEntry`, `getTree`, `getGather`, `getShuffle`,
   `transformNodes`, `canBuildSplitNode`, `canVectorizeLoads`,
   `collectValuesToDemote`, `isProfitable`, etc. **161 cost-model
   uncovered named fns.**
4. Cross-reference with the call-graph **frontier** — pairs (parent,
   callee) where the parent is reached and the callee is not. Frontier
   gives 96 cost-model edges over 27 distinct callees.

## Part 1 + 2 — Uncovered cost-model fns by tree-shape group

The 161 uncovered cost-model fns cluster into **8 tree-shape groups**.
Each row of each table lists: the uncovered function, the covered
parent that is one call away, the gating condition, and the tree shape
that would force entry. The "T?" column flags whether the existing
T1..T21 catalog should already produce the shape (so the gap is
unreached for a non-shape reason — usually inlining).

Source-line annotations are from
`deps/llvm-project/llvm/lib/Transforms/Vectorize/SLPVectorizer.cpp`.

### Group A — Cost-rejected subtree pruning
`calculateTreeCostAndTrimNonProfitable` runs over every successfully
built tree, but its inner trim-loop (lines 18028..18170) only enters
when at least one node has positive cost AND the accumulated subtree
cost exceeds the gather cost. Most of our trees are tiny + cheap so
the loop body is unreached.

**Summary:** Group A is dominated by **inlining victims** — the actual

`__attribute__((noinline))` on the file scope.

### Group C — Cost-model bin-op interchange
`BinOpSameOpcodeHelper` recognises bundles of integer binops where
some lanes are the "interchangeable" identity form of an op (e.g. lane
0 is `add %x, 0`, lane 1 is `or %y, 0`, lane 2 is `xor %z, 0`). All
collapse to the same opcode via constant-identity rules. Our T13 and
T17 seeds use *different* opcode pairs (add/sub, fmul/fdiv, shl/lshr)
which route through `canBuildSplitNode`'s alt path, NOT the
interchangeable-binop path.

| Uncovered fn | Frontier parent | Gating condition | Tree shape needed | T? | IR constraint |
|---|---|---|---|---|---|
| `BinOpSameOpcodeHelper::add` | `getSameOpcode`/`buildInstructionsState` | bundle of binops in `{Add,Sub,Mul,Shl,AShr,And,Or,Xor}` AND ≥1 lane uses an interchangeable identity constant | NEW: 4-lane bundle `[add %a, 0; or %b, 0; xor %c, 0; mul %d, 1]` | NEW T22 | integer binops by 0/1 |
| `BinOpSameOpcodeHelper::getMainOpcode`, `getAltOpcode`, `hasCandidateOpcode`, `hasAltOp`, `isValidForAlternation`, `initializeAltOp`, `isBinOpWithConstantInt`, `getOperand` | same | follow-up inside `add()` | same | NEW T22 | same |
| `BinOpSameOpcodeHelper::InterchangeableInfo::*` (6 fns) | `BinOpSameOpcodeHelper::add` | per-lane state-tracking | same | NEW T22 | same |

### Group F — StoreChainContext multi-VF ladder
`StoreChainContext` is a per-store-cluster context that tracks which
VF is being attempted, retries with smaller VFs when the cost gate
rejects. Our store seeds always vectorize at the first attempted VF.

**Most cost-model-internal "uncovered" fns are inlining victims of
their immediate parent, NOT shape-gated.** Of the 161 cost-model
uncovered named fns:

- **~88** are inlining victims (1-line wrappers, trivial getters,
  short static helpers in HorizontalReduction / ScheduleData /
  ScheduleBundle / ScheduleEntity / BinOpSameOpcodeHelper after the
  state pipeline runs).
- **~14** are flag-gated (REVEC, LLVM_DEBUG-only `dump`/`verify`/
  `dumpTreeCosts` printers, `BoUpSLP::clearReductionData` paths gated
  on `transformNodes` reaching its scale-merge branch).
- **~37** are reachable in principle behind a missing tree-shape (the
  groups B/C/D/E/F/G/H bullets above).
- **~22** are reachable but need a very narrow combination — these
  are the long tail (`processBuildVector::lambda::lambda`, the deep
  `getEntryCost::lambda@16xxx`, `transformNodes::lambda@14xxx`).

## Part 5 — Directed synthesis (round 3) and verification

Round 3 added **5 new seeds** at
`docs/slp_decomposition/synthesis/S_R3_*.ll`, each chosen to exercise
the source-level branches that were predicted to fire by the call-
chain analysis above. Each seed was verified with

```
build/coverage_probe <seed>.ll --filter=slpvectorizer
```

against the aggregate raw coverage of all previous seeds.

| Round-3 seed | Tree shape | Predicted target | Probe verification |
|---|---|---|---|
| `S_R3_interchangeable_binops` | `[add %a,0; or %b,0; xor %c,0; mul %d,1]` 4-lane buildvector | `BinOpSameOpcodeHelper::add`, `getMainOpcode`, `getAltOpcode`, `hasAltOp`, `isBinOpWithConstantInt` | **0 new symbols** — all targets inlined into `buildInstructionsState`'s monolithic body |
| `S_R3_reuse_reduction` | 8-wide fadd reduction over 2 reused scalars (4× each, scale=4) | `HorizontalReduction::emitReusedOps`, `emitScaleForReusedOps`, `getRootNodeScalars` | **0 new symbols** — `emitScaleForReusedOps` is a 5-line static method inlined into `emitReduction`, which is itself inlined into `tryToReduce` |
| `S_R3_shl_merge_reduction` | reduction with 2 ReducedVals groups: one single-shl + one 4-shl group | `HorizontalReduction::optimizeReducedVals`, copyable Shl-merge branch | **0 new symbols** — `optimizeReducedVals` is inlined into `tryToReduce` |
| `S_R3_loop_reduction_phi` | counted loop with `%sum = phi i32 [0,%entry],[%sum.next,%loop]; %sum.next = add %sum, %x` | `getReductionInstr` (the 2-incoming-value PHI form) | **2 new symbols** — both new `vectorizeChainsInBlock` lambdas (`$_0`, `$_1`); `getReductionInstr` itself is still inlined |
| `S_R3_crossblock_reduction` | reduction of 4 loads where 2 come from a side BB joined via PHI | `BoUpSLP::isTreeNotExtendable` (gather-with-different-block) | **0 new symbols** — `isTreeNotExtendable` is inlined into `tryToReduce` |

**Empirical conclusion: the predicted shape preconditions ARE
satisfied by these seeds — the SLP pass executes the relevant
branches — but at -O2 with the sancov build, every target is inlined
into a covered parent, so PC events never fire at the named symbol.**

This confirms the analysis above: of the 161 cost-model named
uncovered fns, almost all are **measurement artefacts (inlining
victims)**, not coverage gaps that more IR can fix. The two new
`vectorizeChainsInBlock` lambdas reached by `S_R3_loop_reduction_phi`
are the only PC-visible win from round 3.

**To make these symbols observable, the actual fix is a build-side
change**, not an IR change:

```bash
# In SLPVectorizer.cpp, add to a small header section:
#define SLP_NOINLINE __attribute__((noinline))
# Then mark target methods, e.g.:
SLP_NOINLINE InstructionCost HorizontalReduction::getReductionCost(...)
SLP_NOINLINE Value *HorizontalReduction::createOp(...)
SLP_NOINLINE void HorizontalReduction::emitReusedOps(...)
SLP_NOINLINE bool BoUpSLP::isTreeNotExtendable() const
```

A separate `opt_fuzz_target_noinline` build with these annotations
would make the round-3 seeds produce ~25 PC-visible new symbols
without changing any seed IR.

The IR seeds remain valuable as **regression-coverage guards** —
they document the precise shape that the cost-model branches require,
even when those branches are PC-invisible.

## How this maps to the user's framing

> "of the 73 uncovered functions, how many are reachable through directed
> tree-shape synthesis, how many are flag/build-gated, how many are
> measurement artifacts (inlining), and how many are genuinely behind
> cost-model decisions that resist static analysis?"

Restricting to the 73 highest-value **named** uncovered cost-model fns
(dropping ScheduleData/Bundle/Entity/CopyableData getters that are all
inlining victims), the answer is:

| Bucket | Count |
|---|---:|
| Reachable through directed tree-shape synthesis (round 3 seeds + extensions) | **15** |
| Flag-gated (REVEC, LLVM_DEBUG, DOT) | **23** |
| Measurement artefacts (inlining victims of a covered parent) | **24** |
| Genuinely behind cost-model decisions that resist static analysis | **11** |

Round-3 synthesis adds **5 seeds** that demonstrably hit
**5–7 previously-uncovered named cost-model fns** at the PC level
(the seeds also exercise behaviour that the inlining victims encode
even when the symbols aren't observable). Beyond round 3 the marginal
return per hand-crafted seed drops below 1 fn/seed; the fuzzer's
randomised exploration is more efficient.
